Purrdr 主機服務

主機服務讓 Purrdr 以 HTTPS 連到你的電腦，不需要在電腦上開 SSH。它只在電腦本機(127.0.0.1)接受連線，由 Tailscale 的 tailscale serve 提供只在你的 tailnet 內連得到的 HTTPS 位址;憑證與加密都由 Tailscale 處理，不經過 Purrdr 的伺服器。

需要準備什麼?

  • macOS(Apple 晶片或 Intel)、Linux(x86_64 或 ARM64)或 Windows(x86_64)。
  • 電腦上執行著 herdr 0.9.5 以上。
  • 電腦與 iPhone／iPad 都安裝 Tailscale 並登入同一個 tailnet。
  • 在 Tailscale 管理主控台的 DNS 頁開啟 MagicDNS 與 HTTPS Certificates。

開啟 HTTPS Certificates 後，電腦的名稱(例如 studio.tail1234.ts.net)會寫進公開的 Certificate Transparency 紀錄。名稱含有不想公開的資訊時，先在 Tailscale 改名。安裝程式也會提醒並徵求你同意(不詢問的安裝要加 --yes 表示同意，見安裝參數)。

安裝

在電腦上開終端機，執行一行指令(不需要 sudo 或系統管理員):

macOS、Linux

curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | sh

Windows(PowerShell)

irm https://github.com/raychiutw/purrdr.host/releases/latest/download/install.ps1 | iex

指令會下載這台電腦適用的版本，以 SHA-256 檢查碼驗證(不符就停止、不留下檔案),再執行 purrdr-host-service install:檢查 Tailscale 設定、把程式放到 ~/.purrdr/host-service/、設定 tailscale serve,並在登入後自動啟動(macOS 是 LaunchAgent,Linux 是 systemd user service,Windows 是登入時執行)。0.6.0 起也會把 purrdr-host-service 加進使用者的 PATH:裝完重開終端機就能直接打 purrdr-host-service(不想改 PATH 時安裝加 --no-path)。

macOS 版以 Apple Developer ID 簽章。Windows 版沒有程式碼簽章，Windows 可能顯示 SmartScreen 警告。

要指定埠或 herdr 的具名 session:macOS／Linux 用 curl -fsSL …/install.sh | sh -s -- --port 47820 --session work;Windows 用 & ([scriptblock]::Create((irm …/install.ps1))) --port 47820 --session work。要安裝特定版本，先設環境變數 PURRDR_HOST_SERVICE_VERSION(例如 0.1.0)。

與其他 tailscale serve 服務並存

主機服務預設使用 HTTPS 443。如果這台電腦的 443 已經被其他工具的 tailscale serve 使用，安裝程式不會更動它：沒指定埠時會自動改用第一個可用的埠(依序 443、8443、9443、10000、10443)並說明原因，最後印出 HTTPS 位址。也可以自己指定埠：macOS／Linux 用 curl -fsSL …/install.sh | sh -s -- --https-port 8443;Windows 用 & ([scriptblock]::Create((irm …/install.ps1))) --https-port 8443。位址會帶上埠號(例如 https://my-mac.tailnet.ts.net:8443),配對的 QR code 與在 Purrdr 輸入的位址都要包含它。之後再執行安裝指令(更新)會沿用同一個埠，解除安裝只關掉主機服務自己的埠。

安裝失敗時，訊息會說明發生什麼與原因，最後一行 Next: 是下一步要執行的完整指令。

也可以從 GitHub Releases 手動下載壓縮檔(附 SHA256SUMS),解壓後執行 purrdr-host-service install。

安裝參數

安裝時每一項設定都可以用參數或環境變數指定。決定順序：參數 > PURRDR_* 環境變數 > 上次安裝的設定 > 預設值,所以重跑安裝不會把你之前選的設定洗掉。

參數環境變數預設值說明
--port <埠>PURRDR_PORT47820主機服務在本機(127.0.0.1)聽的埠。不接受 0。
--https-port <埠>PURRDR_HTTPS_PORT443經 Tailscale Serve 對 tailnet 公開的 HTTPS 埠，決定 Purrdr 連的網址。不接受 0。
--session <名稱>PURRDR_SESSIONherdr 預設 session要連的 herdr 具名 session。
--auto-update、--no-auto-updatePURRDR_AUTO_UPDATE=1|0開(1)是否自動更新。
--path、--no-pathPURRDR_ADD_TO_PATH=1|0加入(1)是否把 bin/ 加進使用者的 PATH。
--yesPURRDR_YES=1否不要求確認，視為同意所有問題。
--json(無)否只印一個 JSON 物件、不詢問;同意憑證公開仍要另外加 --yes。

HTTPS 埠的建議值

沒指定 HTTPS 埠、而 443 已被其他工具的 tailscale serve 使用時，安裝程式不會更動它，而是依序嘗試 443、8443、9443、10000、10443,挑第一個空的，並說明是誰占用了其他的埠。你明確指定的埠被占用才會報錯。位址會帶上埠號(例如 https://my-mac.tailnet.ts.net:8443)。

互動安裝

在終端機執行時，安裝程式先列出這次要套用的設定與每項的來源，再問一次：1) Install with these settings(已安裝過時是 Keep current settings)、2) Customize 逐項調整、3) Cancel 取消。

不詢問的安裝

符合下列任一條件就不會詢問：沒有終端機、設了 CI 環境變數、加了 --yes(或 PURRDR_YES=1)、加了 --json。公開憑證(Certificate Transparency)只在第一次安裝或電腦名稱改變時需要你同意;不詢問又沒有 --yes 時，安裝會在改動任何東西之前停止，並告訴你加 --yes 重跑。

帶參數安裝

macOS、Linux:

curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | sh -s -- --https-port 9443
curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | PURRDR_HTTPS_PORT=9443 sh -s --

Windows(PowerShell):

$env:PURRDR_HTTPS_PORT=9443; irm https://github.com/raychiutw/purrdr.host/releases/latest/download/install.ps1 | iex

之後要修改

  • 自動更新：purrdr auto-update on 或 purrdr auto-update off。
  • 其他設定：重跑 purrdr install --<參數>,例如 purrdr install --https-port 9443。已配對的裝置會保留。

給 AI agent 與腳本

加 --json 會印出一個 JSON 物件。成功時有 ok、https_address、settings(每項是 {value, source},source 為 argument、environment、previous、default、suggested(自動換用建議的 HTTPS 埠)或 prompt)、warnings 與 pair_command;失敗時有 ok: false、error(kind 與 message)、rerun_command,以及已解析到的部分 settings。完整說明見 llms.txt(英文)。

配對 iPhone／iPad

0.10.0 起可以打短指令 purrdr(purrdr help 列出所有指令)。更舊的版本請把下面的 purrdr 換成 purrdr-host-service;自動更新到 0.10.0 的主機在服務重新啟動後就有 purrdr。

  1. 在電腦上執行 purrdr pair。0.6.0 以前的安裝(或加了 --no-path)不在 PATH,要用完整路徑:macOS／Linux 是 ~/.purrdr/host-service/bin/purrdr-host-service pair,Windows PowerShell 是 & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" pair。畫面會顯示 QR code、HTTPS 位址與一次性配對碼。
  2. 用 iPhone 的「相機」App 掃 QR code,或在 Purrdr 的「⋯ → Hosts → +」選 HTTPS,輸入位址與配對碼。
  3. 只想讓這支裝置看、不能操作：改用 purrdr pair --read-only。

列出已配對的裝置：purrdr devices;撤銷一支裝置：purrdr revoke <裝置 ID>。不在 PATH 時同樣用完整路徑，例如 Windows 的 & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" devices。在 Purrdr 刪除這台主機時，也會撤銷這支裝置。

更新

主機服務預設會自動更新：背景服務啟動後幾分鐘先檢查一次，之後每天檢查最新版本;有新版就下載、以 SHA-256 檢查碼驗證(macOS 另驗 Developer ID 簽章)、替換並重新啟動，新版起不來會自動退回原版本。設定、HTTPS 埠與已配對的裝置都會保留。

  • 查看版本：purrdr version(已安裝與最新版本、自動更新開關、上次檢查的時間與結果)。
  • 只檢查有沒有新版：purrdr update --check。
  • 立刻更新：purrdr update(加 --yes 不詢問)。
  • 關閉自動更新：purrdr auto-update off(on 再打開);安裝時也可以加 --no-auto-update,例如 macOS／Linux 用 curl -fsSL …/install.sh | sh -s -- --no-auto-update,Windows 用 & ([scriptblock]::Create((irm …/install.ps1))) --no-auto-update。

0.6.0 起安裝後重開終端機就能直接打上面的指令。0.6.0 以前的安裝(或加了 --no-path)要用完整路徑：macOS／Linux 例如 ~/.purrdr/host-service/bin/purrdr-host-service update,Windows PowerShell 例如 & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" update。

0.4.x 以前的主機服務沒有更新功能：先重跑一次上面的安裝指令(會保留已配對的裝置),之後才會開始自動更新。Purrdr 發現主機服務比它知道的版本舊時，會在主機清單提示更新並依主機的版本附上指令。

查看狀態與解除安裝

  • 狀態：purrdr status(是否安裝、HTTPS 位址、herdr 是否在執行)。
  • 解除安裝：purrdr uninstall。會停止自動啟動、移除 tailscale serve 設定與 ~/.purrdr/host-service/,電腦回到安裝前的狀態。

透過 HTTPS 能做什麼?

Agent 列表、聊天、送出 prompt、回答「需要你」與 Pane 終端機都可以用。登入 Shell 與檔案目前只有 SSH 連線方式提供。

Purrdr Host Service

The host service lets Purrdr connect to your computer over HTTPS, with no SSH server needed. It only accepts connections on the computer itself (127.0.0.1); Tailscale’s tailscale serve gives it an HTTPS address that’s reachable only inside your tailnet. Tailscale handles the certificate and encryption, and nothing goes through Purrdr’s servers.

What do I need?

  • macOS (Apple silicon or Intel), Linux (x86_64 or ARM64), or Windows (x86_64).
  • herdr 0.9.5 or later running on the computer.
  • Tailscale on both the computer and your iPhone or iPad, signed in to the same tailnet.
  • MagicDNS and HTTPS Certificates turned on in the DNS page of the Tailscale admin console.

With HTTPS Certificates on, the computer’s name (like studio.tail1234.ts.net) is written to public Certificate Transparency logs. If the name contains anything you’d rather keep private, rename the machine in Tailscale first. The installer reminds you and asks before continuing (installs that can’t ask need --yes to agree; see Install options).

Installing

Open a terminal on the computer and run one command (no sudo or administrator needed):

macOS, Linux

curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | sh

Windows (PowerShell)

irm https://github.com/raychiutw/purrdr.host/releases/latest/download/install.ps1 | iex

The command downloads the build for this computer, verifies its SHA-256 checksum (stopping without leaving files behind if it doesn’t match), and runs purrdr-host-service install, which checks your Tailscale settings, puts the program in ~/.purrdr/host-service/, sets up tailscale serve, and starts it when you sign in (a LaunchAgent on macOS, a systemd user service on Linux, a sign-in entry on Windows). From 0.6.0 it also adds purrdr-host-service to your user PATH: open a new terminal after installing and type purrdr-host-service directly (install with --no-path to leave PATH alone).

The macOS build is signed with an Apple Developer ID. The Windows build isn’t code-signed, so Windows may show a SmartScreen warning.

To choose a port or a named herdr session: on macOS and Linux, curl -fsSL …/install.sh | sh -s -- --port 47820 --session work; on Windows, & ([scriptblock]::Create((irm …/install.ps1))) --port 47820 --session work. To install a specific version, set PURRDR_HOST_SERVICE_VERSION (for example 0.1.0) first.

Sharing tailscale serve with other services

The host service uses HTTPS port 443 by default. If another tool on this computer already uses 443 with tailscale serve, the installer leaves it alone: when you haven’t chosen a port it switches to the first free one (443, 8443, 9443, 10000, 10443), explains why, and prints the final HTTPS address. You can also choose the port: on macOS and Linux, curl -fsSL …/install.sh | sh -s -- --https-port 8443; on Windows, & ([scriptblock]::Create((irm …/install.ps1))) --https-port 8443. The address then includes the port (for example https://my-mac.tailnet.ts.net:8443), and so do the pairing QR code and any address you type in Purrdr. Running the install command again (updating) keeps the same port, and uninstalling only turns off the host service’s own port.

If the install fails, the message says what happened and why, and its last Next: line is the full command to run next.

You can also download an archive from GitHub Releases (with SHA256SUMS), extract it, and run purrdr-host-service install.

Install options

Every install setting can be given as an option or an environment variable. Order of precedence: option > PURRDR_* environment variable > the previous install > default, so installing again never wipes out what you chose before.

OptionEnvironment variableDefaultWhat it does
--port <port>PURRDR_PORT47820The port the host service listens on, on this computer only (127.0.0.1). 0 is not accepted.
--https-port <port>PURRDR_HTTPS_PORT443The HTTPS port Tailscale Serve exposes to your tailnet; it decides the address Purrdr connects to. 0 is not accepted.
--session <name>PURRDR_SESSIONherdr’s default sessionThe named herdr session to connect to.
--auto-update, --no-auto-updatePURRDR_AUTO_UPDATE=1|0on (1)Whether to update automatically.
--path, --no-pathPURRDR_ADD_TO_PATH=1|0add (1)Whether to add bin/ to your user PATH.
--yesPURRDR_YES=1noDon’t ask for confirmation; answers yes to every question.
--json(none)noPrints one JSON object and never asks; it still needs --yes to agree to the certificate notice.

The suggested HTTPS port

When you don’t choose an HTTPS port and 443 is already used by another tool’s tailscale serve, the installer leaves that alone: it tries 443, 8443, 9443, 10000, then 10443, picks the first free one, and tells you what is using the others. It only fails if a port you explicitly chose is taken. The address then includes the port (for example https://my-mac.tailnet.ts.net:8443).

Interactive install

In a terminal, the installer first lists the settings it is about to use and where each came from, then asks once: 1) Install with these settings (Keep current settings if already installed), 2) Customize to go through them one by one, or 3) Cancel.

Installing without questions

It never asks when any of these is true: there is no terminal, the CI environment variable is set, you passed --yes (or PURRDR_YES=1), or you passed --json. Publishing the certificate (Certificate Transparency) needs your consent only the first time or when the computer’s name changes; when it can’t ask and there is no --yes, the install stops before changing anything and tells you to run again with --yes.

Installing with options

macOS, Linux:

curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | sh -s -- --https-port 9443
curl -fsSL https://github.com/raychiutw/purrdr.host/releases/latest/download/install.sh | PURRDR_HTTPS_PORT=9443 sh -s --

Windows (PowerShell):

$env:PURRDR_HTTPS_PORT=9443; irm https://github.com/raychiutw/purrdr.host/releases/latest/download/install.ps1 | iex

Changing settings later

  • Auto update: purrdr auto-update on or purrdr auto-update off.
  • Anything else: run purrdr install --<option> again, for example purrdr install --https-port 9443. Paired devices are kept.

For AI agents and scripts

--json prints one JSON object. On success it has ok, https_address, settings (each one is {value, source}, where source is argument, environment, previous, default, suggested (an automatically chosen HTTPS port), or prompt), warnings, and pair_command; on failure it has ok: false, error (kind and message), rerun_command, and the settings resolved so far. The full reference is in llms.txt (English).

Pairing your iPhone or iPad

From 0.10.0 you can type the short command purrdr (purrdr help lists every command). On older versions, replace purrdr below with purrdr-host-service; hosts that updated themselves to 0.10.0 get purrdr once the service restarts.

  1. On the computer, run purrdr pair. Installs older than 0.6.0 (or with --no-path) aren’t on PATH, so use the full path: ~/.purrdr/host-service/bin/purrdr-host-service pair on macOS and Linux, or & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" pair in Windows PowerShell. It shows a QR code, the HTTPS address, and a one-time pairing code.
  2. Scan the QR code with the iPhone Camera app, or in Purrdr go to “⋯ → Hosts → +”, choose HTTPS, and enter the address and pairing code.
  3. For a device that can watch but not act, use purrdr pair --read-only instead.

List paired devices with purrdr devices; revoke one with purrdr revoke <device ID>. If it isn’t on PATH, use the full path here too, for example & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" devices on Windows. Deleting the host in Purrdr also revokes that device.

Updating

The host service updates itself by default: a few minutes after it starts, and then every day, it checks for the latest version; when there is a newer one it downloads it, verifies its SHA-256 checksum (and the Developer ID signature on macOS), replaces itself, and restarts. If the new version doesn’t start, it goes back to the previous one. Settings, the HTTPS port, and paired devices are kept.

  • Version: purrdr version (installed and latest version, whether auto update is on, and the last check and its result).
  • Only check for a newer version: purrdr update --check.
  • Update now: purrdr update (--yes skips the question).
  • Turn auto update off: purrdr auto-update off (on turns it back on). You can also install with --no-auto-update: on macOS and Linux, curl -fsSL …/install.sh | sh -s -- --no-auto-update; on Windows, & ([scriptblock]::Create((irm …/install.ps1))) --no-auto-update.

From 0.6.0, open a new terminal after installing and these commands work as written. Installs older than 0.6.0 (or with --no-path) need the full path, for example ~/.purrdr/host-service/bin/purrdr-host-service update on macOS and Linux, or & "$HOME\.purrdr\host-service\bin\purrdr-host-service.exe" update in Windows PowerShell.

Host service 0.4.x and earlier can’t update itself: run the install command above once more (paired devices are kept), and it starts updating itself from then on. When Purrdr sees a host service older than the version it knows about, it shows an update notice in the host list with the command for that host’s version.

Status and uninstalling

  • Status: purrdr status (whether it’s installed, its HTTPS address, and whether herdr is running).
  • Uninstall: purrdr uninstall. It stops the sign-in start, removes the tailscale serve setting and ~/.purrdr/host-service/, and leaves the computer as it was before installing.

What works over HTTPS?

The Agent list, chats, sending prompts, answering “Needs You”, and Pane terminals all work. Login Shell and Files are currently available only with SSH.
